# SIPL Language Toolkit

Набір інструментів для простої мови програмування SIPL із навчального курсу:
формальна граматика, типізоване абстрактне синтаксичне дерево (AST) з позиціями
у вихідному тексті, парсер, інтерпретатор з обмеженням виконання, трасування
подій, візуалізація дерева синтаксичного виводу, інтерфейс командного рядка з
підтримкою JSON та інтеграція з відладчиком VS Code через Debug Adapter Protocol.

Реалізація спирається на граматику SIPL із курсу «Теорія програмування»
М. С. Нікітченка та умову проєктної роботи. Узгоджені правила пріоритету
операцій наведено у [граматиці SIPL](grammar/SIPL.ebnf).

## Реалізовані модулі

Це навчальний проєкт для університету, а не опублікований пакет чи реліз.
Реалізовано такі модулі:

| ID | Бали | Модуль |
| --- | ---: | --- |
| CORE-01 | 0.5 | Машинозчитувана граматика та позитивні й негативні синтаксичні тести |
| CORE-02 | 1.5 | Парсер із типізованим AST і діагностикою з позиціями у вихідному тексті |
| CORE-03 | 2.0 | Інтерпретатор, стан цілочисельних змінних та обмеження виконання |
| CORE-04 | 1.0 | Трасування початку й завершення операторів, умов і змінних |
| CORE-05 | 1.0 | Команди CLI `parse`, `check`, `run` і `trace` з підтримкою JSON |
| IDE-03 | 2.5 | Відладчик VS Code: точки зупину, крокування, продовження, змінні та обчислення виразів |
| VIS-01 | 1.5 | Дерево синтаксичного виводу у форматах text, JSON і DOT |

Заявлена сума за ці модулі становить **10.0 балів** згідно з умовою проєкту;
остаточне оцінювання залежить від приймання роботи викладачем. Завдання з
публікації, створення релізів і автоматизації CI не обрано.

## Вимоги та встановлення

Потрібен Python 3.10 або новіший. Встановіть пакет у режимі розробки:

```sh
python -m pip install -e ".[dev]"
```

Пакет не має сторонніх залежностей для виконання. `pytest`, `coverage` та
`build` використовуються лише для розробки й перевірки.

## Командний рядок

```sh
sipl parse examples/power.sipl
sipl parse examples/power.sipl --json
sipl check examples/power.sipl
sipl run examples/power.sipl --state '{"X": 3, "Y": 4}'
sipl trace examples/power.sipl --state '{"X": 3, "Y": 4}' --json
sipl tree examples/power.sipl --format text
sipl tree examples/power.sipl --format json
sipl tree examples/power.sipl --format dot
```

Команди повертають `0` у разі успіху та `2` за некоректного вводу, синтаксичної
помилки, помилки виконання, некоректного JSON або помилки введення-виведення.
JSON-вивід призначений для інтеграції з іншими інструментами. Команди `run` і
`trace` приймають необов'язковий початковий стан у вигляді JSON-об'єкта, який
зіставляє імена змінних із цілими числами. Параметр `--max-steps` обмежує
кількість виконаних операторів, зокрема складених; типове значення — `100000`.
Команда `check` перевіряє синтаксис; про невизначену змінну повідомляється під
час її обчислення.

Формати успішного JSON-виводу:

| Команда | Результат |
| --- | --- |
| `parse --json` | Об'єкт AST із полями `type`, полями вузла та `span` |
| `check --json` | `{"valid": true, "diagnostics": []}` |
| `run --json` | `{"state": {"name": 1}, "steps": 1}` |
| `trace --json` | `{"trace": [event, ...]}` |
| `tree --format json` | Об'єкт дерева з полями `symbol`, `kind`, `span`, `text` і `children` |

Подія трасування містить поля `event`, `span`, `statement`, `condition`,
`changes`, `state` і `steps`; непридатні для конкретної події поля мають
значення `null`. Помилки мови в режимі JSON записуються в stderr у форматі
`{"error": {"code": "...", "message": "...", "span": ...}}`; помилки
введення-виведення чи значень аргументів мають поле `message`. Кінцева позиція
діапазону вихідного тексту не входить до нього.

## Синтаксис SIPL

Парсер підтримує:

- програму `begin ... end`;
- присвоювання, послідовності, блоки, `skip`, `if ... then ... else` та `while`;
- цілі числа, змінні, унарний мінус, операції `+`, `-`, `*`, `=`, `>`, `¬` та
  `∨` (ASCII-символ `|` є альтернативним записом `∨`).

Множення має вищий пріоритет, ніж додавання й віднімання; операції одного
пріоритету групуються зліва направо. Диз'юнкція має нижчий пріоритет, ніж
заперечення. Ці правила усувають неоднозначність компактного запису БНФ у курсі.
Оголошень і локальних областей видимості немає: змінна створюється присвоюванням.
Читання змінної до присвоювання або без значення в початковому стані спричиняє
помилку виконання з позицією у вихідному тексті.

## Трасування та API

```python
from sipl import parse, run

program = parse("begin X := X + 1 end")
result = run(program, {"X": 2})
assert result.state == {"X": 3}
for event in result.trace:
    print(event.to_dict())
```

Трасування містить події `BeforeStatement`, `AfterStatement`, `VariableChanged`,
`BeforeCondition` (перед кожною перевіркою умови циклу), `ConditionEvaluated`
та `ExecutionFinished`; кожна пов'язана з кодом подія має діапазон `SourceSpan`.
Трасування створює той самий інтерпретатор, що використовується для виконання та
налагодження.

## Дерево синтаксичного виводу

Команда `tree` візуалізує конкретний синтаксис, розпізнаний тим самим парсером,
який будує AST. Дерево містить правила граматики та їхні термінальні токени,
зокрема дужки, ключові слова, роздільники та EOF; на відміну від AST воно не
відкидає ці синтаксичні деталі. Ідентифікатори й цілі числа подаються як токени
лексера. Пробільні символи ігноруються лексером, але входять до фрагментів
вихідного тексту вузлів, що їх охоплюють.

У форматах text і DOT відображається діапазон вихідного тексту кожного вузла;
JSON також містить точний текст відповідного фрагмента. Нумерація рядків і
стовпців починається з 1, а зміщення — з 0 і відповідають позиціям у рядку
Python; кінцева позиція не входить до діапазону. Вузли DOT також містять
фрагмент вихідного тексту як підказку. DOT можна зберегти та, за потреби,
перетворити на SVG встановленою командою Graphviz `dot`:

```sh
sipl tree examples/power.sipl --format dot > power.dot
dot -Tsvg power.dot -o power.svg
```

Дерево також доступне через бібліотечний API:

```python
from sipl import parse_with_tree
from sipl.visualization import format_tree_text, tree_to_data

program, tree = parse_with_tree("begin X := (1 + 2) end")
print(format_tree_text(tree))
assert tree_to_data(tree)["symbol"] == "program"
```

## Приклади

- `examples/power.sipl`: піднесення до степеня повторним множенням. Запустіть із
  `--state '{"X": 3, "Y": 4}'`; кінцеве значення `R` дорівнює `81`.
- `examples/floor_log.sipl`: обчислення `floor(log_X(Y))` для цілих `X > 1` і
  `Y > 0`; цілочисельна частка обчислюється повторним відніманням. Запустіть із
  `--state '{"X": 3, "Y": 7}'`; кінцеве значення `R` дорівнює `1`.
- `examples/branch.sipl`: абсолютна різниця, обчислена за допомогою розгалуження.

## Тести та збирання

```sh
python -m pytest --cov=sipl --cov-branch --cov-fail-under=80
python -m build
```

Набір синтаксичних тестів містить щонайменше десять коректних і десять
некоректних повних програм SIPL. Тести та перевірку порога покриття можна
запустити локально наведеними вище командами. Розширення VS Code також можна
зібрати локально з каталогу `vscode-sipl/`.

## Відладчик VS Code

Встановіть пакет у той інтерпретатор Python, який задано в `sipl.pythonPath`,
а потім встановіть `vscode-sipl/sipl-debugger-0.1.0.vsix` за допомогою команди
VS Code **Extensions: Install from VSIX**. Відкрийте каталог проєкту та створіть
конфігурацію запуску SIPL, наприклад у `.vscode/launch.json`:

```json
{
  "version": "0.2.0",
  "configurations": [{
    "name": "Debug SIPL power",
    "type": "sipl",
    "request": "launch",
    "program": "${workspaceFolder}/examples/power.sipl",
    "initialState": {"X": 3, "Y": 4},
    "maxSteps": 100000
  }]
}
```

Встановіть точку зупину на операторі та натисніть F5. Точки зупину прив'язані до
діапазонів AST у вихідному тексті; панель **Variables** показує поточний стан
цілочисельних змінних інтерпретатора. Обчислення виразів підтримує арифметичні
вирази, але не виконує оператори SIPL. Помилки виконання відображаються в
консолі налагодження та завершують сеанс із ненульовим кодом.

Адаптер передає повідомлення DAP у стандартному форматі з заголовком
`Content-Length`: протокольні повідомлення надсилаються через stdout,
діагностика — через stderr.
